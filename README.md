# BuckShot Roulette Server

내일배움캠프 단기심화 9기 **5조 BUCKSHOT ROULETTE**의 게임 서버입니다.
원작 "Buckshot Roulette"를 Unity로 다시 만들고 온라인 대전(1대1, 3~4인)으로 넓힌 프로젝트이며, 이 저장소는 그중 서버 코드입니다.

> **클라이언트 저장소는 비공개입니다.**
> 클라이언트(Unity) 저장소에는 원작의 모델·텍스처·음악 같은 에셋이 들어 있어서, 저작권 문제로 부득이하게 비공개로 두고 서버 저장소만 공개합니다.
> 원작의 저작권은 원작자에게 있습니다.

## 기획 요약

### 어떤 게임인가요?
실탄과 공포탄이 섞인 산탄총을 번갈아 쏘는 턴제 게임입니다. 장전된 탄의 개수만 공개되고 순서는 숨겨져 있어서, 상대를 쏠지 나를 쏠지(공포탄이면 한 번 더) 고르는 심리전이 핵심입니다. 돋보기·맥주·담배·수갑·쇠톱 같은 아이템으로 판을 뒤집을 수 있습니다.

### 모드
| 모드 | 내용 |
|---|---|
| 싱글 | AI 딜러와 원작 규칙으로 대결. 승리 시 엔딩, 패배 시 부활 연출 |
| 1대1 온라인 | 빠른 매칭 / 랭크 매칭(레이팅) / 방 코드로 친구와 대전 |
| 3~4인 멀티 | 한 테이블에서 여러 명이 대결, 멀티 전용 아이템, 라운드 결과 화면 |
| 연승 모드 | AI 딜러를 연달아 이기며 기록 경쟁, 리더보드 |

### 목표
- 원작의 분위기와 연출(딜러 손동작, 카메라, 사운드 타이밍)을 그대로 살린다.
- 혼자 하던 게임을 온라인으로 넓히되, **판정은 서버가 해서** 조작을 막는다.
- 연결이 끊겨도 게임이 멈추지 않게 한다.

### 클라이언트와 서버의 역할
| | 클라이언트 (Unity 6, 비공개) | 서버 (이 저장소) |
|---|---|---|
| 맡는 일 | 화면·연출·사운드, 입력, 로비 UI, 싱글 모드 AI 딜러 | 매칭, 탄 장전·턴·사격·아이템 판정, 보상·레이팅 저장 |
| 아는 정보 | 서버가 알려 준 결과만 | 탄 순서를 포함한 게임 전체 상태 |

### 온라인 한 판의 흐름
1. 로그인(REST) → JWT 발급
2. WebSocket 연결 (연결할 때 JWT 검증)
3. 매칭 요청 → '대기 중' → '매칭 완료'
4. 양쪽이 준비되면 서버가 탄을 장전하고 아이템을 나눠 줌
5. 차례가 된 사람이 행동(아이템 사용, 사격 대상 선택)을 보냄 → 서버가 판정해 결과를 모두에게 보냄 → 클라이언트는 결과대로 연출
6. 게임이 끝나면 서버가 경험치·돈·레이팅을 저장하고 결과를 보냄

## 기술 스택

| 구분 | 내용 |
|---|---|
| 언어 / 프레임워크 | Java 21, Spring Boot 4.1 (Web MVC, WebSocket, Data JPA, Validation) |
| 인증 | JWT (jjwt 0.12) |
| DB | MySQL 8.0 |
| 통신 | REST(로그인·랭킹 등) + WebSocket(실시간 대전, JSON 패킷) |
| 인프라 | Docker / Docker Compose, AWS EC2 |
| 테스트 | JUnit 5 (테스트 250개) |

Redis는 Compose에 컨테이너만 구성돼 있고, 현재 코드에서는 쓰지 않습니다. 매칭 대기열은 서버 메모리에 있습니다.

## 주요 기능

- **서버 판정**: 탄 순서, 체력, 턴, 아이템 효과를 모두 서버가 정하고 결과만 클라이언트에 보냅니다.
- **매칭**: 빠른 매칭, 레이팅 기반 랭크 매칭(Elo), 방 만들기·코드로 참가
- **대전**: 1대1, 3~4인 멀티 (원작 아이템 + 멀티 전용 아이템)
- **성장**: 레이팅·티어, 경험치·레벨, 돈 보상, 연승 모드, 리더보드
- **연결 관리**: 중복 접속 차단, 끊긴 연결 감지(10초마다 ping, 20초 무응답 시 종료) 후 이탈 처리

## 폴더 구조

```
src/main/java/com/buckshot
├── auth         로그인, JWT 발급·검증
├── user         유저 정보, 닉네임
├── ws           WebSocket 연결, 패킷 라우팅·전송
├── matchmaking  빠른 매칭 / 랭크 매칭 대기열, 게임 준비
├── game         게임 규칙 (탄창, 탄, 아이템, 체력)
├── devtest      방 만들기·1대1 대전 방 (개발 초기 이름 그대로 사용 중)
├── multi        3~4인 멀티 게임
├── rating       Elo 레이팅, 티어
├── level        레벨 계산
├── reward       경험치·돈 지급
├── streak       연승 모드 기록
├── ranking      리더보드
├── config       Web / WebSocket 설정
└── common       공통 예외·에러 응답
```

## 로컬에서 실행하기

필요한 것: JDK 21, Docker

```bash
# 1. 환경 변수 파일 만들기 (DB_PASSWORD, JWT_SECRET을 채웁니다. JWT_SECRET은 32자 이상)
cp .env.example .env

# 2. MySQL(+Redis) 컨테이너 띄우기
docker compose up -d

# 3. 서버 실행 (http://localhost:8080)
./gradlew bootRun
```

Windows에서는 `start-dev-server.bat`을 실행하면 2~3번을 한 번에 합니다.

테스트는 `./gradlew test`로 돌립니다. 테스트는 H2 메모리 DB를 쓰므로 MySQL 없이도 돌아갑니다.

## 배포

`deploy` 브랜치에 푸시하면 EC2의 cron이 1분마다 변경을 확인하고, `docker-compose.prod.yml`로 서버 컨테이너를 다시 빌드합니다. 푸시 후 약 2분 안에 반영됩니다.
운영 환경에서는 8080 포트만 열고, MySQL은 컨테이너 내부 네트워크에서만 접근합니다.
